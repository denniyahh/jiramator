# Requirements: Jiramator

**Defined:** 2026-04-27
**Core Value:** Eliminate repetitive manual Jira issue creation during PI planning by turning declarative configs into bulk-created, correctly-linked Jira issues.

## v1 Requirements

Requirements for current milestone. Each maps to roadmap phases.

### Foundation

- [x] **FOUND-01**: User receives actionable error messages with field/line context when YAML config validation fails
  - *Motivation:* `research: table stakes for config-driven tools`
- [x] **FOUND-02**: User can view a structured execution report (created issues, skipped duplicates, errors) after any plan or import run
  - *Motivation:* `research: prerequisite for rollback and resume`
- [x] **FOUND-03**: User can resume a partially failed bulk creation run from the last failure point without recreating already-created issues
  - *Motivation:* `research: table stakes for bulk operations`

### Template Config

- [x] **TMPL-01**: User can define org-locked default fields and team-internal default fields that flow into ticket templates without per-template repetition
  - *Motivation:* `user: eliminate repetitive field entry across team configs`
- [x] **TMPL-02**: User can see how org and team layers merge via stderr conflict warnings at config-load time and via the visible team-internal `defaults:` block
  - *Motivation:* `research: prevents confusion from implicit merge semantics`

### Issue Creation

- [x] **ISSUE-01**: User can assign created tickets to specific Jira sprints using board_id and sprint name templates in config
  - *Motivation:* `user: saves manual sprint assignment step post-creation`

### Integration

- [ ] **INTG-01**: User can interact with Jiramator via MCP protocol, with plan and import exposed as MCP tools
  - *Motivation:* `user: MCP as primary API path`
- [ ] **INTG-02**: MCP tools operate non-interactively (equivalent to `--yes` flag behavior)
  - *Motivation:* `research: MCP tools cannot answer interactive prompts`
- [ ] **INTG-03**: MCP and REST API paths produce identical results for the same inputs
  - *Motivation:* `research: prevent behavioral divergence between API paths`

### Spreadsheet Import

- [x] **IMPT-01**: User can import spreadsheets with non-UTF-8 encodings (Windows Excel exports) without manual encoding conversion
  - *Motivation:* `research: broader audience uses Windows/Excel`

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Foundation

- **FOUND-04**: User can bulk-delete all issues from a specific run (rollback/undo)
- **FOUND-05**: ✅ **Shipped (v1.0.1)** — User can run plan non-interactively via
  `--yes` (plus `--pi-number`/`--versions`) for CI/scripted usage

### Config

- **CONF-01**: ✅ **Shipped (v1.1.0)** — User can generate org and team config
  files via interactive setup wizard (`jiramator init`, with Jira field-ID
  auto-discovery)
- **CONF-02**: User can diff two team configs to see what changed between PIs

### Issue Creation

- **ISSUE-02**: User can create sub-tasks linked to parent stories (not just epics)
- **ISSUE-03**: User can query existing issues before creation to avoid duplicates (improved duplicate detection)
- **ISSUE-04**: User can run plan for multiple teams in one command (multi-team orchestration)
- **ISSUE-05**: User can export dry-run preview as Markdown/HTML for sharing with stakeholders

### Spreadsheet Import

- **IMPT-02**: User can filter rows based on conditions during import
- **IMPT-03**: User can import from multi-sheet Excel files

## Out of Scope

| Feature | Reason |
|---------|--------|
| Full Jira issue update/sync engine | Upsert semantics on Jira are complex (transitions, permissions). Turns creation tool into sync engine with 10x complexity |
| Web UI / dashboard | CLI is the strength. MCP integration meets users where they already are |
| Jira workflow automation (transitions, webhooks) | Jira Automation's domain. Reimplementing is a maintenance trap |
| Multi-Jira-instance support (Cloud + Server) | Server API differs enough to require parallel codepaths. Cloud-only is defensible |
| Plugin/extension system | Expensive to maintain for a niche tool. Config-driven approach preferred |
| Confluence automation | Future vision, not current milestone |
