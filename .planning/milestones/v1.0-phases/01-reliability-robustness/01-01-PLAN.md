From RESEARCH.md (the canonical SafeLineLoader pattern, already verified to execute on this system):
```python
import yaml

LINE_KEY = "__line__"

class SafeLineLoader(yaml.SafeLoader):
    def construct_mapping(self, node, deep=False):
        mapping = super().construct_mapping(node, deep=deep)
        mapping[LINE_KEY] = node.start_mark.line + 1   # 1-indexed
        return mapping

def safe_load_with_lines(stream) -> object:
    return yaml.load(stream, Loader=SafeLineLoader)
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User filesystem → loader | YAML file path passed via `--team-config` / `--org-config`. Path is user-controlled, contents are user-controlled. |
| Loader → Pydantic → builder | `__line__` markers cross this boundary. Untrusted shape: anything Pydantic permits (including `dict[str, Any]` fields). |
| Builder → Jira API | Outbound payload. Must NOT carry `__line__` keys or anything not derived from sanitized inputs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `__line__` marker leaking into Jira ticket payload corrupts ticket field with internal metadata | mitigate | `_strip_line_markers` called as first line of `_build_fields_payload` (Task 3 edit B); integration test S4 covers real config end-to-end |
| T-01-02 | Information Disclosure | Error message includes user's CWD-resolved absolute path, may leak directory structure in shared logs | accept | Acceptable — paths are already echoed by `cli.py:118` (existing); FOUND-01 strictly improves over status quo. No new disclosure |
| T-01-03 | Denial of Service | Pathological YAML (deeply-nested aliases, billion-laughs) triggers loader hang | mitigate | `yaml.SafeLoader` is the existing class we subclass; SafeLoader rejects the `!yaml` tag and other unsafe constructs by inheritance. No additional surface. |
| T-01-04 | Information Disclosure | `did_you_mean` could leak field names from a config the user shouldn't see | accept | Out of scope — single-user CLI tool, all input is the user's own config |
| T-01-05 | Tampering | Crafted YAML maps `__line__` key explicitly to a poison value | mitigate | Loader overwrites `__line__` AFTER `super().construct_mapping(...)` returns, so any user-provided `__line__` gets clobbered; strip helper catches it on the builder side regardless |
</threat_model>
