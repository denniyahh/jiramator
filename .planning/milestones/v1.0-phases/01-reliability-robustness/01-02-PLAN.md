<objective>
Land IMPT-01 (CSV import accepts non-UTF-8 encodings without manual conversion). Build a small, deterministic encoding-detection module and wire it into `spreadsheet._read_csv`. Accept an `encoding_override` parameter on `read_spreadsheet` so the eventual `--encoding` CLI flag (added in Plan 05) has a contract to call.

Purpose: Today, `spreadsheet.py:21` is hardcoded to `encoding="utf-8"`. A user opening a CSV that Excel-on-Windows exported (with smart quotes, em-dash, `£`, `°`, or curly apostrophes in names like `O'Brien`) sees `UnicodeDecodeError` with no actionable next step. After this plan, BOM-flagged files just work, plain UTF-8 just works, and cp1252-and-friends are detected with a visible stderr announcement so the user can verify the assumption.

From RESEARCH.md §"Pattern 5: Encoding fallback chain" (canonical implementation, verified empirically):
```python
import codecs
from pathlib import Path

_BOM_TABLE = (
    (codecs.BOM_UTF8, "utf-8-sig"),
    (codecs.BOM_UTF16_LE, "utf-16"),    # Python's "utf-16" handles either-endian when BOM is present
    (codecs.BOM_UTF16_BE, "utf-16"),
)

def detect_encoding(path: Path, *, override: str | None = None) -> str:
    if override:
        return override
    with path.open("rb") as f:
        head = f.read(4)
    for sig, enc in _BOM_TABLE:
        if head.startswith(sig):
            return enc
    raw = path.read_bytes()
    try:
        raw.decode("utf-8")
        return "utf-8"
    except UnicodeDecodeError:
        pass
    from charset_normalizer import from_bytes
    best = from_bytes(raw).best()
    if best is None:
        raise ValueError(
            f"Could not detect encoding for {path}. "
            f"Re-save as UTF-8 or pass --encoding <name> "
            f"(try --encoding cp1252 or --encoding utf-16-le)."
        )
    return best.encoding
```
