<objective>
Wire the run-report substrate (Plan 03) into the two execution engines, and add the `_template_key` annotation that makes per-issue resume identity deterministic. After this plan, every `plan` and `import` invocation produces a JSON run report on disk; passing a prior report into either function makes them skip already-created issues.

Purpose: FOUND-02 (always-emitted run report) and FOUND-03 (resume) cannot be split — resume requires the report exists, the report has no value if nothing consumes it, and both depend on the `_template_key` annotation being present in the same place. Plans 03 + 04 = the full FOUND-02+03 surface; Plan 05 = CLI flags.

- `ticket_builder.py` mutated: every payload returned by `build_all()` carries `_template_key`; `_strip_template_key()` helper added; `_strip_line_markers` (added in Plan 01) and `_template_key` are siblings in the strip-before-send convention.
- `planner.py` mutated: `run_plan()` signature gains `report_path: Path | None`, `prior_report: RunReport | None`, `force: bool`; report is `write_report_atomic`-ed after every state change; epic creation skips refs already in prior report; bulk creation filters out already-created template_keys.
- `importer.py` mutated: `run_import()` signature gains the same kwargs; row results emit incrementally; resume skips rows whose template_key is already created.
- New tests covering: template-key generation, drift detection, skip-on-resume for both engines, persist-on-error.

<!-- The annotation scheme this plan introduces (deterministic, stable across reruns): -->
```
epic ref_key="bau"                  → "epic:bau"
per_release[i] template_idx=0, version="26.1.1"   → "per_release[0]:26.1.1"
per_release[i] template_idx=2, version="26.2.0"   → "per_release[2]:26.2.0"

```
The `template_idx` is the position of the template in the team_config list — stable as long as the user doesn't reorder templates. Reordering invalidates resume (which is what the resolved-config-hash drift check catches).
