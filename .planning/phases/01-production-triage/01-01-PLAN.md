<objective>
Implement INV-04 (D-12, D-13): when `plan` or `import` exits on an exception or deliberate abort,
the run report records `ended_at` and an `error` record (`{type, message}`) before re-raising,
while every pre-existing report still loads and resumes.

Purpose: all five zero-count `failed` production reports are indistinguishable today because the
`except BaseException` handlers persist state but not the cause. This makes future failures
self-explaining and is the fix that closes the "unrecorded exit" class found by triage.
Output: extended `run_report.py`, error recording in planner/importer/cli, regression tests, CHANGELOG entry.

Design decisions (agent's discretion per CONTEXT, locked here and in tests):
- Field: `error: dict[str, str] | None = None`, last field of `RunReport`; shape `{"type": str, "message": str}`.
- `SCHEMA_VERSION` stays 1 (an additive optional field is not a migration; `test_4_schema_version_two_rejected` keeps its contract).
- `to_envelope` omits `error` when it is None (resolves RESEARCH A3 per user-unavailable default) → clean reports byte-compatible with v1.2.8.
- `from_envelope` ignores unknown keys (forward compatibility for future additive fields).
- Deliberate aborts use the stable label `"Aborted"` (constant `ABORTED_ERROR_TYPE`) with the printed reason as message (resolves RESEARCH open question 3).
- D-13 is rated **costly** (not one-way) in CONTEXT → flagged on Task 1, no decision checkpoint.
</objective>
