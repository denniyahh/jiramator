## Resolved open questions (recorded assumptions — user may override)

- **OQ-1 (yes — user-reviewable assumption):** import calls the validator with `skip_allowed_value_field_ids=frozenset({"issuetype"})`. Issue-type validity is already enforced by the casefold match against the createmeta issue-type list (D-02), and the validator's option check is case-sensitive, so checking it again would false-positive on `risk` vs `Risk`. D-07 text said "empty set"; this is a small refinement for user sign-off. fixVersions is still validated for import exactly as D-07 requires.
- **OQ-2 (adopt RESEARCH recommendation — dry-run/live parity):** `import --dry-run --resume` passes `prior_report` into the dry-run `run_import`, which applies the same prior-created skip set the live run uses. Dry-run therefore validates exactly the rows a live resume would attempt. Without `--resume`, dry-run validates every row that built (D-08).
- **OQ-4 (include, in Plan 04):** non-numeric `number` cells become per-row build errors (Plan 04 Task 2).
- **OQ-5 (yes):** if the issue-type list fetch or ANY per-type field fetch fails, the whole preflight is `unavailable` (D-02 availability path) — no partial results.
- **Stub contract with Plan 02:** tests in Plan 02 stub createmeta with a dict subclass whose `get()` returns a non-required descriptor for any field id. Every on-screen/off-screen decision in find_payload_problems and run_preflight must therefore go through `field_metadata.get(field_id)` (already the existing per-field pattern); never derive off-screen status from `keys()` or iteration.
- **Flagged assumption (edge PRE-04, unclassified, unresolved):** the PRE-04 degrade path is assumed to need no further edge handling beyond: no-credentials, get_fields failure, createmeta unavailable (auth/permission/network/5xx). Any other degrade trigger (e.g. a malformed createmeta body that parses but lacks `fields`) is NOT specified and is left unresolved for user review.
