## Resolved open questions (recorded assumptions — user may override)

- **OQ-3 (follow D-08 literally):** rows that would be skipped by summary dedup (`find_issue_keys_by_summaries`) are still validated, because preflight runs before that lookup. Interaction: re-running an import where some rows already exist in Jira can abort on a problem in an already-existing row (e.g. the 2026-09-02 184255Z re-run). Recorded for user review; changing it would require moving the dedup lookup before preflight.
- **OQ-5:** any createmeta fetch failure = whole preflight `unavailable` (from Plan 01).
- **Build-failed rows:** when preflight ran, they are part of the abort list (D-08); when unavailable, today's behaviour (recorded failed, other rows created) is kept.
